# hcn/formalization/

This is the Lean 4 project of the class number two proof. It proves `HCN.classNumber_le_two_iff` and
`HCN.classNumber_eq_two_iff` without Heegner's method (no j-invariant or singular moduli occur in the closure), linear forms
in logarithms, or Gross–Zagier. It is pinned exactly as the first proof in
[`../../formalization/`](../../formalization/README.md) is:
- Lean v4.34.1;
- openai/math at commit [`adc7f124`](https://github.com/openai/math/tree/adc7f1241b42e322a6451854ab7e4b4c146bf78a), which provides
  the zero-free region Re s > 7/8 for Dirichlet L-functions;
- the Mathlib revision that openai/math uses, d13f23b723b8a846827a245b89c10fc7d3f11612.

[`lake-manifest.json`](lake-manifest.json) pins the same 43 packages at the same revisions as the first proof's manifest, and
[`scripts/apply_oai_patches.sh`](scripts/apply_oai_patches.sh) is the first proof's patch script, byte for byte.

## The libraries

| Library | What it is |
|---|---|
| `HCNChallenges` | [`HCNChallenges/ClassNumberLeTwo.lean`](HCNChallenges/ClassNumberLeTwo.lean), the two statements with `sorry`. It imports only Mathlib. Its two sets are generated from computed class-number data by [`../certificates/gen_sets.py`](../certificates/README.md). |
| `HCN` | The new development. [`HCN/Main.lean`](HCN/Main.lean) is the solution module: it states both theorems exactly as the challenge does, and proves them. |
| `CN1` | The first proof's 41 modules, vendored verbatim from [`../../formalization/CN1/`](../../formalization/CN1) (byte-identical). This proof uses its foundations, its analysis, its numerics, its positivity `L(7/8, χ) ≥ 0`, and its main theorem `CN1.classNumber_eq_one_iff` for the nine fields of class number one. The first proof's challenge library is not vendored, because nothing here needs it. |
| `HCNNegControls` | The three tampered statements, which Comparator must reject against `HCN.Main`: [`Tamper/Move163.lean`](HCNNegControls/Tamper/Move163.lean) (163 moved into the class-number-two set), [`Tamper/DropSquarefree.lean`](HCNNegControls/Tamper/DropSquarefree.lean) and [`Tamper/Swap431.lean`](HCNNegControls/Tamper/Swap431.lean) (427 replaced by 431, whose class number is 21). They are generated from the challenge by [`../certificates/gen_controls.py`](../certificates/README.md), and never imported by `HCN`. |

## The modules, step by step

| Step of the argument | Module | Main declarations |
|---|---|---|
| Chowla–Selberg for a general positive form `a x² + b x y + c y²`, with the explicit remainder bound `Bg` and its monotonicity in `a`; it specializes to the first proof's formula at `a = 1` | `HCN.Statements.GeneralCS`, with helpers `HCN.CS.Form`, `.Slice`, `.MainTerm`, `.Remainder`, `.Mono` | `CS_main_general`, `norm_Eg_seven_eighths_le`, `Bg_mono`, `CS_main_principal` |
| `ζ_K` as a sum over the nonzero ideals | `HCN.Epstein.IdealZeta` | `hasSum_dedekindZeta` |
| The partition `ζ_K = Σ_C ½ Z_{Q_C}`, with Hermite bases and representatives of norm at most `(2/3)√d` | `HCN.Statements.ClassPartition` | `exists_isHermite`, `hasSum_classSum`, `exists_classReps` |
| The numerics at `s = 7/8`: for every real `D ≥ 4778`, the bound for the principal class and the bound for the sum are positive | `HCN.Numerics.Threshold` | `Pv_pos_and_add_Tv_pos` |
| The analytic threshold: `4778 ≤ dOf m ⇒ 3 ≤ classNumber K` | `HCN.Assembly.LowerBound` | `three_le_classNumber_of_ge`, `dOf_le_4777_of_classNumber_le_two` |
| Non-representation by the principal form, decided by the kernel | `HCN.Finite.NotRep` | `NotRep`, `NotRep.sound` |
| Class number at least three from a certificate of chosen split primes, with no forms–ideals bridge | `HCN.Finite.ClassLower` | `ClassCert`, `le_classNumber_of_cert_foundations` |
| The 1,429 certificates for the fields with `dOf m ≤ 4777` and `h ≥ 3` (generated) | `HCN.Finite.Certs`, `.Certs.Chunk1` … `.Chunk15` | `hcnGe3`, `three_le_classNumber_of_mem` |
| The range lemma: every other field below 4778 is in `hcnGe3` (generated) | `HCN.Assembly.Range` | `mem_hcnGe3_of_range`, `three_le_classNumber_of_lt` |
| The class group is generated by primes below the Minkowski bound | `HCN.Finite.Generation` | `mem_of_forall_prime_le_minkowski` |
| Class number exactly two from a bridge certificate, for the eighteen (generated data) | `HCN.Finite.IdealLite`, `HCN.Finite.ClassTwo` | `classNumber_eq_two_of_bridge`, `classNumber_eq_two_of_mem` |
| The assembly, with one `lt_or_ge (dOf m) 4778` (generated) | `HCN.Assembly` | `classNumber_le_two_iff_of_facts`, `classNumber_eq_two_iff_of_facts` |
| The two theorems (generated from a template) | `HCN.Main` | `HCN.classNumber_le_two_iff`, `HCN.classNumber_eq_two_iff` |

The generated files are produced by the scripts in [`../certificates/`](../certificates/README.md), which also check that the
checked-in files are exactly what they produce.

## Building

You need [elan](https://github.com/leanprover/elan), git and Python 3. From this directory:

```sh
scripts/apply_oai_patches.sh              # fetch the pinned packages and apply openai/math's patches (once)
lake exe cache get                        # download the Mathlib build cache
lake build HCN CN1 HCNChallenges          # the proof, the vendored first proof, and the statements
```

The patch script is the first proof's; its README explains why it is needed, and why you must not run `lake update`.
openai/math and its dependencies are compiled from source, which is the long part; [`VERIFICATION.md`](VERIFICATION.md) records
a build of a fresh copy of this directory, with its wall time and job count. Plan for about 23 GB of disk, and for one module,
the generated range lemma `HCN.Assembly.Range`, that needed about 26 GB of memory on its own.

## Checking the axioms, and the one rule

```sh
printf 'import HCN.Main\n\n#print axioms HCN.classNumber_le_two_iff\n#print axioms HCN.classNumber_eq_two_iff\n' > AxiomCheck.lean
lake env lean AxiomCheck.lean > axioms.out && scripts/check_axioms.sh axioms.out
```

This should print `OK: HCN.classNumber_le_two_iff and HCN.classNumber_eq_two_iff depend only on standard axioms`. Lake's own
warnings (it reports the 23 patched packages as "local changes") go to standard error, so only Lean's output is checked.
[`scripts/check_axioms.sh`](scripts/check_axioms.sh) removes all whitespace, because Lean prints a long axiom list one entry per
line, and then requires the *whole* output to be the two reports, in order, in which every entry is one of `propext`,
`Classical.choice` and `Quot.sound`. Anything else fails: an error line, a further report, or an axiom whose name contains a
bracket. [`scripts/check_no_sorry.sh`](scripts/check_no_sorry.sh) requires a build log that reports success and contains exactly
two `sorry` warnings, those of the two challenge statements. [`scripts/test_checks.sh`](scripts/test_checks.sh) runs both scripts
over the accept and reject cases in [`scripts/fixtures/`](scripts/fixtures). These are the determinant route's scripts, adapted
to two theorems.

**The one rule.** Do not write a file that imports `HCN.Main` together with `HCNChallenges.ClassNumberLeTwo` or any module under
`HCNNegControls/`. All of them declare the two theorem names, and Lean silently merges same-type declarations on import:
`#print axioms` then reports the cached axioms of one module for the proof term of another. Use Comparator (challenge
`HCNChallenges.ClassNumberLeTwo`, solution `HCN.Main`), or check the axioms in a file whose only project import is `HCN.Main`,
as above. `#print axioms` reads a summary stored with the compiled modules, so even used correctly it is a convenient check,
not the strongest one; the run of record also walked the closure of both theorems directly.

## Checking with Comparator

The configurations are in [`comparator/`](comparator):

| Configuration | Challenge | Expected verdict |
|---|---|---|
| [`ClassNumberLeTwo.json`](comparator/ClassNumberLeTwo.json) | the two statements | "Your solution is okay!" (nanoda and Lean's kernel both accept) |
| [`Tamper_Move163.json`](comparator/Tamper_Move163.json) | 163 moved into the class-number-two set | rejected: statement mismatch for `HCN.classNumber_eq_two_iff` |
| [`Tamper_DropSquarefree.json`](comparator/Tamper_DropSquarefree.json) | `Squarefree m` dropped | rejected: statement mismatch for `HCN.classNumber_le_two_iff` |
| [`Tamper_Swap431.json`](comparator/Tamper_Swap431.json) | 427 replaced by 431 | rejected: statement mismatch for `HCN.classNumber_le_two_iff` |

Each permits only `propext`, `Quot.sound` and `Classical.choice`, with nanoda switched on. Run them as for the first proof: build
Comparator at tag v4.34.0 with its `lean4export`, and nanoda; set `COMPARATOR_LEAN4EXPORT`, `COMPARATOR_NANODA` and
`COMPARATOR_LANDRUN`; then `lake env comparator comparator/<config>.json` from this directory. landrun is Linux-only; our runs
were on macOS, with a pass-through shim in its place, so they were **not sandboxed**.

## The published files and the checked files

The run of record was made on a tree whose comments still carried internal references (plan section numbers, the names of work
tracks and review items, private paths). We removed those from the comments and docstrings, and corrected one docstring figure
in `HCN.Numerics.Threshold`; nothing else in the Lean sources changed. The generators were changed in the same way, so that
they now produce the published files. The build configuration (`lakefile.lean`, `lake-manifest.json`) is replaced by the
public one, which takes openai/math from git instead of a local checkout. The vendored first-proof modules are the
already-published copies, which differ from the copies in the run of record only in comments. [`VERIFICATION.md`](VERIFICATION.md)
records how we checked all of this on the compiled declarations, and a fresh Comparator run on the published files.
